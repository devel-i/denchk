## 1. Разработка алгоритмов

### Требования

Настольное приложение должно позволять входить по логину из списка пользователей без пароля, различать роли администратора и пользователя, показывать ФИО вошедшего, возвращаться к экрану входа. Администратор добавляет, изменяет и удаляет подразделения, должности и сотрудников. Удаление подразделения или должности, на которые ссылается сотрудник, запрещено. Пользователь просматривает список сотрудников, ищет по имени или фамилии, фильтрует по подразделению и сортирует по окладу. Операции применяются сразу; показаны число всех и найденных записей.

Среда разработки: Visual Studio 2022, .NET 8, WPF, Entity Framework Core, SQLite. Операционная система для настольной части — Windows. Данные хранятся локально. Интерфейс состоит из экрана входа, вкладки списка и вкладки редактирования, доступной администратору. Сообщения об ошибках и подтверждение удаления имеют заголовок и пиктограмму.

### Функциональная схема

```text
Ввод логина → Проверка в Users → Определение роли
                            ├─ Пользователь → Список сотрудников → Поиск/фильтр/сортировка
                            └─ Администратор → Список + CRUD → Проверка данных → EF Core → SQLite
```

### Диаграмма прецедентов (текстовое представление)

```text
Пользователь: вход, просмотр сотрудников, поиск, фильтр, сортировка, выход.
Администратор: все действия пользователя + добавление, изменение, удаление
подразделения, должности и сотрудника.
```

### Проектирование базы данных

Концептуальный уровень: у подразделения может быть много сотрудников; у должности может быть много сотрудников; каждый сотрудник относится к одному подразделению и одной должности. Пользователь системы имеет логин, ФИО и роль.

Логический уровень:

| Таблица | Основные поля | Связи |
|---|---|---|
| Departments | Id, Name, Location | 1:M с Employees |
| Positions | Id, Name, Salary | 1:M с Employees |
| Employees | Id, LastName, FirstName, MiddleName, HireDate, DepartmentId, PositionId | M:1 с Departments и Positions |
| Users | Id, Login, FullName, IsAdmin | Справочник логинов |

Физический уровень: SQLite; `Id` — первичный ключ, `DepartmentId` и `PositionId` — внешние ключи с запретом каскадного удаления. Уникальные индексы заданы для названий подразделений, названий должностей и логинов. Схема создаётся методом `EnsureCreated()` при первом запуске. Исходный код — `desktop/HrPractice/Models.cs`.

### Алгоритмы

Авторизация: убрать пробелы по краям логина → найти точное совпадение в `Users` → при отсутствии показать ошибку → при наличии показать ФИО и доступные для роли вкладки.

Вывод списка: загрузить сотрудников вместе с подразделением и должностью → применить выбранное подразделение (или «Все») → поиск подстроки по фамилии либо имени без учёта регистра → сортировку по окладу → обновить таблицу и счётчики. Изменение строки поиска и выпадающих списков запускает этот алгоритм без кнопки.

Удаление родительской записи: найти сотрудников с соответствующим внешним ключом → при наличии запретить удаление и вывести подсказку → иначе запросить подтверждение → удалить запись.

## 3. Проект руководства пользователя

**Назначение.** Программа предназначена для учёта сотрудников, подразделений и должностей.

**Установка и запуск.** Открыть `HrPractice.csproj` в Visual Studio на Windows, восстановить пакеты NuGet и нажать «Запустить». База данных создаётся автоматически при первом запуске.

**Вход.** Ввести `isivanov` для роли администратора или `papetrov` для роли пользователя. Пароль по заданию не требуется. Кнопка «Назад / выход» возвращает к входу.

**Просмотр.** На вкладке «Сотрудники» видны ФИО, подразделение, должность и оклад. Ввести текст в поле «Поиск», выбрать подразделение и направление сортировки. «Все» отменяет фильтр. Внизу показаны общее число и число отображаемых сотрудников. Сообщение «Ничего не найдено» означает пустой результат.

**Редактирование.** Администратор выбирает подразделение или должность в таблице, меняет поля и нажимает «Изменить». Для добавления вводит данные и нажимает «Добавить». Для сотрудника сначала выбирает строку в первой вкладке. Удаление требует подтверждения. Перед удалением подразделения или должности следует перевести связанных сотрудников. Нельзя оставлять обязательные поля пустыми; оклад должен быть числом от 0 до 10 000 000.

**Возможные ошибки.** «Логин не найден» — проверить введённый логин. «Выберите ...» — выделить строку таблицы. Ошибка связи — сначала изменить сотрудников. Ошибка базы данных — проверить доступ к файлу базы и свободное место.

## 7. Рефакторинг и оптимизация

Первоначальный подход — отдельная проверка логина, прав и обработка исключения в каждом обработчике кнопки. После рефакторинга повторяющиеся действия вынесены в `Execute(Action action)`, `Admin()`, `ShowError()` и `Confirm()`. Чтение, поиск, фильтрация и сортировка объединены в `ApplyFilter()`, поэтому один и тот же код используется при каждом изменении параметров. Это уменьшает число повторяющихся веток и упрощает исправление ошибок.

```csharp
// До: повторять в каждом обработчике
try { /* действие */ db.SaveChanges(); Refresh(); }
catch (Exception ex) { MessageBox.Show(ex.Message); }

// После: общий метод Execute(Action action)
Execute(() => db.Departments.Add(new Department { Name = name, Location = location }));
```
